# Quickstart: マスタデータ変更のSocket同期漏れ解消

## 前提

- `pnpm dev`でfrontend（`localhost:5173`）・backend（`localhost:3000`）を起動済み
- 管理者アカウントでログイン、別ブラウザ（またはシークレットウィンドウ）でホール/キッチン画面を開いている

## 1. カテゴリ・サブカテゴリ変更のスタッフ間即時反映（User Story 1・4-4）

1. ブラウザAでホール画面（`/hall`等）を開いたままにする
2. ブラウザBで管理画面からカテゴリ名を変更する
3. ブラウザAを再読み込みせずに新しいカテゴリ名が表示されることを確認する
4. 同様にサブカテゴリの作成・削除・並び順変更でも確認する
5. キッチン画面・グループ詳細画面でも同様に確認する

期待結果: [data-model.md](data-model.md)の新規イベント（`category:*`/`subCategory:*`）が`store:${storeId}`ルームへ配信され、画面操作なしで反映される（SC-001）。

## 2. 品切れ変更の客用画面への即時反映（User Story 2・4-5）

1. 客用QR注文画面（客用グループのURL）をブラウザCで開き、対象商品がカートに追加可能であることを確認する
2. スタッフ画面（ブラウザA）から同商品を品切れに変更する
3. ブラウザCを再読み込みせずに、同商品が品切れ表示に変わりカートに追加できなくなることを確認する
4. 品切れ解除でも同様に確認する

期待結果: `menu:soldout`イベントが新規`customer-store:${storeId}`ルームにも配信され、客用画面に反映される（SC-002・SC-003）。

## 3. 権限境界の回帰確認（SC-004）

1. 客用ゲスト接続（ブラウザCのブラウザ開発者ツール、Networkタブ）で、Socket.ioのWebSocketフレームを確認する
2. `order:*`・`group:updated`（他グループ分）・`session:updated`・`settings:updated`など、スタッフ限定イベントが客用ゲスト接続に届いていないことを確認する
3. 他店舗（別サブドメイン）のカテゴリ・サブカテゴリ変更が、対象外の店舗のスタッフ・客用画面に届かないことを確認する

## 4. 回帰確認（通常時）

- `pnpm --filter backend test` / `pnpm --filter frontend test`
- `pnpm test:e2e`（既存スイートに新規イベント追加による破壊的変更がないこと）
