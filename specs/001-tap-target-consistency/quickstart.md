# Quickstart: タップ領域サイズの不整合を解消する

## 1. 前提

- `pnpm --filter frontend dev`でVite dev serverを起動し、ブラウザの開発者ツールでモバイル表示（375px幅程度）に切り替える。

## 2. 視覚回帰の確認（変更前後でスクリーンショット比較）

1. `AppHeader`が表示される任意の画面（例: ホール画面）を開き、ハンバーガーメニューの見た目を確認する。
2. `GroupDetail`画面を開き、QR表示・席変更ボタンの見た目を確認する。
3. 客用注文画面（`CustomerOrder`、QRコード経由でアクセス）を開き、「店員を呼ぶ」「お会計」ボタンの見た目を確認する。
4. `CancelModal`（注文キャンセル数選択）または`CourseTab`（コース人数変更）で`QuantityPicker`の±ボタンの見た目を確認する。
5. いずれも変更前とサイズ・色・アイコンの見た目が同一であることを確認する（当たり判定のみ拡張のため）。

## 3. 当たり判定の確認（開発者ツール）

1. 各対象ボタンをブラウザの開発者ツールで検証し、算出スタイル（Computed）の`min-width`/`min-height`（またはクリック可能要素の実寸）が44px以上であることを確認する。
2. モバイル表示で、ボタンの視覚的な円/アイコンの端から数px外側をタップしてもクリックハンドラが発火することを確認する。

## 4. 隣接ボタンの重なり確認

- `AppHeader`の戻る矢印ボタンとハンバーガーメニューが両方表示される画面（例: `breadcrumb`付き画面）で、当たり判定拡張後も誤タップが起きないか目視確認する。
- `GroupDetail`のQR表示・席変更ボタンが並ぶ箇所も同様に確認する。

## 5. 回帰確認

- `pnpm --filter frontend typecheck` / `pnpm --filter frontend test` を実行し、既存テスト・新規追加テストがすべて成功することを確認する。
- `pnpm test:e2e` のうち対象画面（ホール、GroupDetail、CustomerOrder、CancelModal/CourseTab関連）に回帰がないことを確認する。
