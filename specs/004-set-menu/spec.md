# Feature Specification: セットメニュー機能

**Feature Branch**: `004-set-menu`

**Created**: 2026-07-20

**Status**: Draft

**Input**: User description: "セットメニュー機能。ラーメンチャーハンセットがあるとして、ラーメンを味噌や醤油から選ぶことができ、チャーハンも五目や海鮮から選べるような、セットメニュー機能が欲しい。また、注文をした場合、厨房にはチャーハンとラーメンが別で入るとよい。ただし、○○セットの枠組みで注文されたことがわかるようになっているべき。"

## Clarifications

### Session 2026-07-23

- Q: セットメニューを1回の注文操作で複数個（同じ内訳で）まとめて注文できるか？ → A: 数量指定可能。既存の単品商品と同じ数量UIで、同じ内訳のセットを複数個まとめて確定できる。
- Q: セットメニュー自体を管理者が明示的に品切れにできるか？ → A: できない。枠の選択肢が全滅した場合の自動非活性のみで対応する。
- Q: セット選択肢として登録された既存商品は、単品メニューとしても引き続き注文可能か？ → A: 影響なし。登録有無に関わらず単品メニューとして引き続き注文できる（参照関係のみ）。
- Q: セットメニューの管理画面は既存の商品管理画面に統合するか、専用画面を新設するか？ → A: 既存の商品管理画面に統合する。セットメニューは特殊な種別の商品として同じ一覧・同じ導線で管理する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理者がセットメニューの構成を作成する (Priority: P1)

管理者は「ラーメンチャーハンセット」のようなセット商品を作成し、その中に「ラーメン」「チャーハン」といった枠を設定し、各枠に選べる商品（味噌ラーメン、醤油ラーメン／五目チャーハン、海鮮チャーハンなど）を登録する。

**Why this priority**: セットの構成が定義できなければ、注文・厨房・伝票の後続シナリオが成立しない。

**Independent Test**: 管理画面で「ラーメンチャーハンセット」を作成し、「ラーメン」枠に2商品、「チャーハン」枠に2商品を登録し、保存後に再表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** セットメニューを新規作成する、**When** 管理者が名称・価格を設定する、**Then** セット商品として保存される。
2. **Given** 作成済みのセット商品、**When** 管理者が「ラーメン」枠を追加し、「味噌ラーメン」「醤油ラーメン」を選択肢として登録する、**Then** 枠と選択肢が一覧に表示される。
3. **Given** 「ラーメン」枠・「チャーハン」枠がそれぞれ選択肢を持つセット、**When** 設定を保存する、**Then** 注文時にこの2枠から選択させる状態になる。

---

### User Story 2 - スタッフ・客がセットメニューを注文する (Priority: P2)

注文画面でセットメニューを選ぶと、枠ごとに選択肢が提示され、各枠から1つずつ選んで1回の注文としてセットを確定できる。

**Why this priority**: セットが構成できても、実際に注文できなければ価値が生まれない。

**Independent Test**: 「ラーメンチャーハンセット」を選び、「味噌ラーメン」と「五目チャーハン」を選択して注文し、会計金額がセット価格通りになることを確認する。

**Acceptance Scenarios**:

1. **Given** 「ラーメンチャーハンセット」（ラーメン枠・チャーハン枠あり）、**When** 「味噌ラーメン」と「五目チャーハン」を選んで注文する、**Then** 1件のセット注文として確定し、会計金額はセット価格になる（内訳商品の個別価格は加算されない）。
2. **Given** ある枠の選択肢の商品が品切れ中、**When** 注文画面でその枠を選ぶ、**Then** 品切れの選択肢は選べない状態で表示される。
3. **Given** 同じ来店グループ、**When** 同じセットメニューをもう一度、別の内訳の組み合わせで注文する、**Then** それぞれ独立したセット注文として記録される。

---

### User Story 3 - 厨房・伝票でセット注文の内訳が適切に表示される (Priority: P3)

セット注文が確定すると、厨房の調理チケットにはラーメンとチャーハンが別々のチケットとして届き、それぞれ独立して調理・提供できる。一方、伝票や注文履歴では、この2品が「ラーメンチャーハンセット」という枠組みの中にまとまって表示される。

**Why this priority**: 業務運用上必須の要件だが、P1・P2が成立していることが前提。

**Independent Test**: セット注文後、厨房画面でラーメンとチャーハンが別チケットとして表示されること、注文履歴画面ではその2品が「ラーメンチャーハンセット」の配下にまとまって表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 確定済みの「ラーメンチャーハンセット」注文、**When** 厨房画面を確認する、**Then** 「味噌ラーメン」と「五目チャーハン」がそれぞれ独立した調理チケットとして表示される。
2. **Given** 同じ注文、**When** 注文履歴・伝票画面を確認する、**Then** 「ラーメンチャーハンセット」という単位の下に、選択された2品がまとめて表示される。

---

### Edge Cases

- ある枠の選択肢が全て品切れの場合、そのセットメニュー自体が注文不可であることが分かる表示になる（自動判定によるものであり、セットメニュー自体に管理者が個別設定する品切れフラグは持たない）。
- セットの内訳商品のうち1品だけを個別にキャンセルする操作は提供しない。キャンセルはセット単位で行う。
- セットメニューの枠構成・価格を変更しても、既存の注文記録の内容・金額には影響しない。
- 枠に登録された商品が管理者によって削除された場合、その商品は選択肢から除外される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理者は既存の商品管理画面上でセットメニュー（親商品）を作成し、名称・価格を設定できる。セットメニューは既存商品と同じ一覧・同じ導線で管理される、特殊な種別の商品として扱う。
- **FR-002**: 管理者はセットメニューに1つ以上の枠（例：「ラーメン」「チャーハン」）を設定できる。
- **FR-003**: 各枠には、既存商品から選択可能な複数の選択肢を登録できる。登録は既存商品への参照であり、その商品の単品メニューとしての注文可否には影響しない。
- **FR-004**: 注文時、利用者は各枠から1つずつ選択し、数量を指定してセットを1回の注文として確定できる（既存の単品商品と同じ数量指定操作）。
- **FR-005**: セット注文が確定すると、各枠で選択された商品は指定した数量分、個別の注文明細として生成される。
- **FR-006**: 生成された個別の注文明細は、どのセット注文に属するかが分かるように紐付けられる。
- **FR-007**: 厨房の調理チケットには、セットの内訳商品が個別のチケットとして表示される。
- **FR-008**: 伝票・注文履歴では、セットの内訳商品はセット単位でまとめて表示される。
- **FR-009**: セット注文の会計金額はセット価格として計上され、内訳商品の個別価格は加算されない。
- **FR-010**: 管理者はセットメニューの枠構成・選択肢・価格を編集・削除できる。
- **FR-011**: 枠の選択肢のうち品切れ中の商品は、注文時に選択できない。

### Key Entities *(include if feature involves data)*

- **セットメニュー**: 親となる商品。名称、価格を持つ。
- **セット枠**: セットメニューに属する内訳の分類（例：「ラーメン」枠）。名称、表示順を持つ。
- **セット枠の選択肢**: 枠に属する個々の商品への参照（既存の商品を参照する）。
- **セット注文（親明細）**: 1回のセット注文単位を表す注文明細。セット価格・数量を持つ。
- **セット内訳注文（子明細）**: 各枠で選択された商品ごとの個別注文明細。親のセット注文と紐付けを持ち、親と同じ数量を持つ。価格は0円（セット価格に含まれるため）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理者は1つのセットメニューの枠構成（枠2つ・各枠選択肢2つ程度）を3分以内に設定できる。
- **SC-002**: セット注文の内訳商品が厨房チケットに個別表示されなかった事象が発生しない。
- **SC-003**: 伝票・注文履歴でセットの内訳商品がセット単位と紐付かずに表示される事象が発生しない。
- **SC-004**: セット注文の会計金額に、内訳商品価格の二重計上などの誤りが発生しない。

## Assumptions

- 既存のCourse機構（来店グループ単位で1つだけ適用される定額制の仕組み）とは別物として設計する。セットメニューは注文のたびに何回でも追加注文できる、注文明細（OrderItem）単位で完結する新規のデータモデルとする。
- セットのキャンセル・取消は「セット単位」で行う。内訳商品の一部だけを個別に取り消す運用は本機能のスコープ外とする。
- セットの各枠は択一選択とする（1枠につき1商品を選ぶ）。
- セットメニュー自体への商品オプション機能（別Feature「003-product-options」）の適用は本仕様のスコープ外とし、必要になった場合は別途仕様化する。
