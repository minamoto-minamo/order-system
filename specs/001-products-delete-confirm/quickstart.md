# Quickstart: 商品管理画面の削除操作に確認ステップを追加する

実装後、以下の手順で3種類の削除操作すべてに確認ステップが機能することを手動検証できる。自動テストの詳細は `tasks.md` を参照。

## 前提

```bash
pnpm setup
pnpm --filter backend db:migrate
pnpm --filter backend db:seed
pnpm dev
```

管理者アカウントでログインし、`/admin/products`（商品管理画面）を開く。

## 検証シナリオ

### 1. 商品削除（User Story 1 / P1）

1. 任意の商品をタップして編集モーダルを開く。
2. 「削除」ボタンをタップする。
3. **期待結果**: 編集モーダルが閉じ、「（商品名）を削除しますか？」の確認シートが表示される。商品はまだ一覧に残っている。
4. キャンセルをタップする。
5. **期待結果**: 確認シートが閉じる。編集モーダルは再表示されない。商品は削除されていない。
6. 再度同じ商品を開いて「削除」→確認シートで削除を確定する。
7. **期待結果**: 商品が一覧から消える。API（`DELETE /api/menus/:id` 相当）が呼ばれていることをネットワークタブで確認する。

### 2. 小分類削除（User Story 2 / P2）

カテゴリ・小分類の削除はカスケード削除を行わず、配下に商品が残っている場合は409で拒否される既存仕様（バックエンド）である。確認ステップの文言もこれに合わせている。

1. 商品が1件以上ある小分類を選び、編集モーダルを開く。
2. 「削除」ボタンをタップする。
3. **期待結果**: 「（小分類名）を削除しますか？配下に商品がある場合は削除できません」の確認シートが表示される。
4. 削除を確定する。
5. **期待結果**: 配下に商品が残っているため削除は失敗し、エラートーストが表示される。小分類・商品は一覧に残る。
6. 配下の商品をすべて削除してから、同じ小分類で再度「削除」→確定する。
7. **期待結果**: 小分類が一覧から消える。

### 3. カテゴリ削除（User Story 3 / P3）

1. 小分類・商品を含むカテゴリを選び、編集モーダルを開く。
2. 「削除」ボタンをタップする。
3. **期待結果**: 「（カテゴリ名）を削除しますか？配下に小分類・商品がある場合は削除できません」の確認シートが表示される。
4. 削除を確定する。
5. **期待結果**: 配下に小分類・商品が残っているため削除は失敗し、エラートーストが表示される。カテゴリ・配下データは一覧に残る。
6. 配下の小分類・商品をすべて削除してから、同じカテゴリで再度「削除」→確定する。
7. **期待結果**: カテゴリが一覧から消える。選択中だった小分類がこのカテゴリ配下にあった場合、選択状態が解除される。

## 単体テストの実行

```bash
pnpm --filter frontend test -- Products
```

`Products.tsx` の削除確認フロー（確認ステップの表示・キャンセル時の非削除・確定時の削除API呼び出し）を検証するテストが通ることを確認する。
