# Feature Specification: 商品オプション機能

**Feature Branch**: `003-product-options`

**Created**: 2026-07-20

**Status**: Draft

**Input**: User description: "商品オプション機能：商品にオプション（選択肢）を設定できるようにする。梅酒のような商品には「ロック」「ソーダ」などの無料選択肢を設定できる。レモンサワーのような商品には「メガサイズ」「濃いめ」など追加課金が発生する選択肢を設定できる。既存のCourse/DrinkPlan機構とは別物として設計する。オプションは商品(MenuItem)に対して設定し、注文時（OrderItem）に選択したオプションと追加課金額を記録できる必要がある。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理者が商品にオプションを設定する (Priority: P1)

管理者は、既存の商品（梅酒・レモンサワーなど）に対して、オプションの分類（例：「氷の状態」「サイズ」）を作成し、その中に選択肢（例：「ロック」「ソーダ」「メガサイズ」）とそれぞれの追加金額（0円可）を登録できる。

**Why this priority**: オプションが設定できなければ、後続の注文・厨房・会計の全てのシナリオが成立しない。他の全機能の土台となる。

**Independent Test**: 管理画面で商品に1つのオプション分類と2つ以上の選択肢（うち1つは追加課金あり）を設定し、保存後に商品詳細で内容が再表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 「梅酒」という商品が存在する、**When** 管理者が「氷の状態」オプション分類を作成し「ロック」「ソーダ」を追加金額0円で登録する、**Then** 商品の設定画面にその2つの選択肢が表示される。
2. **Given** 「レモンサワー」という商品が存在する、**When** 管理者が「サイズ」オプション分類を作成し「メガサイズ」を追加金額付きで登録する、**Then** 選択肢一覧に追加金額が表示される。
3. **Given** オプション分類が設定済みの商品、**When** 管理者がオプション分類を「注文時に選択必須」に設定する、**Then** 未選択のまま注文確定できないことが後続シナリオで保証される。

---

### User Story 2 - スタッフ・客が注文時にオプションを選択する (Priority: P2)

注文画面（ホール/客用）で、オプションが設定された商品を選ぶと、オプション分類ごとに選択肢が提示され、1つを選んで注文できる。追加課金がある選択肢を選ぶと、その商品の会計金額に反映される。

**Why this priority**: 設定されたオプションが実際の注文フローで使えて初めて業務価値が生まれる。

**Independent Test**: オプション設定済みの商品を注文し、追加課金選択肢を選んだ場合に注文明細の金額が「商品価格＋追加金額」になることを確認する。

**Acceptance Scenarios**:

1. **Given** 「氷の状態」オプション（任意）が設定された「梅酒」、**When** 「ソーダ」を選択して注文する、**Then** 注文明細に「ソーダ」が記録され、追加金額は発生しない。
2. **Given** 「サイズ」オプション（任意、メガサイズ+200円）が設定された「レモンサワー」、**When** 「メガサイズ」を選択して注文する、**Then** 注文明細の金額に+200円が反映される。
3. **Given** 「注文時に選択必須」に設定されたオプション分類がある商品、**When** オプションを選択せずに注文しようとする、**Then** 注文は確定できず、選択を促される。
4. **Given** オプションが設定されていない商品、**When** 通常通り注文する、**Then** 従来通りオプション選択なしで注文できる。

---

### User Story 3 - 選択したオプションが厨房・会計に正しく反映される (Priority: P3)

注文で選択されたオプションは、厨房の調理チケットに表示され、会計時にはオプションの追加金額を含めた正しい金額が計上される。

**Why this priority**: 業務運用として、厨房が正しい内容を調理でき、会計が正しい金額になることは必須だが、P1・P2が成立していることが前提となるため優先度は3番目。

**Independent Test**: オプション付きの商品を注文し、厨房画面にオプション名が表示されること、会計画面の合計金額にオプション追加分が含まれることを確認する。

**Acceptance Scenarios**:

1. **Given** 「メガサイズ」を選択した「レモンサワー」の注文、**When** 厨房画面を確認する、**Then** 調理チケットに商品名とあわせて「メガサイズ」が表示される。
2. **Given** オプション追加課金を含む複数商品の注文、**When** 会計画面を確認する、**Then** 合計金額にすべてのオプション追加金額が正しく合算されている。

---

### Edge Cases

- オプション分類・選択肢が1つも設定されていない商品は、従来通りオプションなしで注文できる。
- 「注文時に選択必須」なオプション分類の選択肢を管理者が全て削除した場合、その商品は選択肢が存在せず注文確定できない状態になる。管理画面上で警告を表示する。
- 過去の注文で選択されたオプションの追加金額は、注文確定時点の金額を記録し、後から管理者がオプションの金額を変更しても過去の注文金額は変わらない。
- 商品からオプション分類の紐付けを解除・削除しても、過去の注文記録（明細）は削除・変更されない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理者は商品（MenuItem）に対して1つ以上のオプション分類を設定できる。
- **FR-002**: 各オプション分類には1つ以上の選択肢を設定でき、各選択肢には追加金額（0円を含む）を設定できる。
- **FR-003**: 管理者はオプション分類ごとに「注文時に選択必須」か「任意」かを設定できる。
- **FR-004**: 注文時、選択必須のオプション分類が未選択の場合、注文を確定できない。
- **FR-005**: 各オプション分類内では、選択肢を1つだけ選択できる（択一）。
- **FR-006**: 注文明細（OrderItem）には、選択されたオプションと、選択時点での追加金額が記録される。
- **FR-007**: 会計金額には、選択されたオプションの追加金額が商品価格に加算されて反映される。
- **FR-008**: 厨房画面の調理チケットには、選択されたオプションの名称が表示される。
- **FR-009**: 管理者はオプション分類・選択肢を編集・削除できる。
- **FR-010**: 商品からオプション分類の紐付けを解除・削除しても、既存の注文記録の内容・金額は変更されない。

### Key Entities *(include if feature involves data)*

- **オプション分類（ProductOptionGroup）**: 商品に紐づくオプションの分類。名称、必須/任意フラグ、表示順を持つ。1つの商品に複数のオプション分類を設定できる（例：「氷の状態」と「サイズ」を別分類として持てる）。
- **オプション選択肢（ProductOptionChoice）**: オプション分類に属する個々の選択肢。名称、追加金額、表示順を持つ。
- **注文明細オプション選択**: 注文明細（OrderItem）に紐づき、選択された選択肢と、選択時点の追加金額のスナップショットを保持する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理者は1つの商品に対するオプション分類・選択肢の設定を2分以内に完了できる。
- **SC-002**: オプション選択を伴う注文の会計金額に、追加金額の計上漏れ・誤りが発生しない。
- **SC-003**: 厨房担当者は伝票を別途確認することなく、調理チケット上の表示だけでオプション内容を判断できる。
- **SC-004**: 選択必須のオプションが未選択のまま注文が確定される事象が発生しない。

## Assumptions

- オプション分類内の選択肢は択一選択とする。同一分類内で複数選択肢を同時選択する用途（トッピングの複数選択など）は本機能のスコープ外とし、必要な場合は分類を分けて表現する（例：「サイズ」分類と「濃さ」分類を別々に用意すれば両方選べる）。
- 選択肢単位の品切れ設定は本機能のスコープ外とする。品切れは既存の商品全体の品切れ機能を利用する。
- 既存のCourse/DrinkPlan機構（Group単位で適用される定額制の仕組み）とは独立したデータモデルとして設計する。両者の組み合わせ（コース内商品へのオプション適用）は本仕様では対象外とし、必要になった場合は別途仕様化する。
- オプションが設定されていない既存商品は、従来通りオプションなしで注文できる（後方互換）。
