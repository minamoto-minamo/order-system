# Quickstart: 商品オプション機能の検証手順

実装完了後、以下の手順でエンドツーエンドの動作を確認する。

## 前提

```bash
pnpm --filter backend db:migrate   # ProductOptionGroup/ProductOptionChoice/OrderItemOption を反映
pnpm dev                            # frontend + backend 起動
```

管理者アカウントでログイン済みであること。

## シナリオ1: オプション分類・選択肢の設定（User Story 1 / FR-001〜003, 009）

1. 管理画面 `/admin/products` で任意の商品（例: 梅酒）を開く。
2. オプション分類「氷の状態」を追加し、選択肢「ロック」（0円）「ソーダ」（0円）を追加して保存する。
3. 商品詳細を再表示し、2つの選択肢が表示されることを確認する（[spec.md](./spec.md) Acceptance Scenario 1-1）。
4. 別商品（例: レモンサワー）にオプション分類「サイズ」・選択肢「メガサイズ」（+200円）を追加し、保存後に金額が表示されることを確認する（Acceptance Scenario 1-2）。
5. 「氷の状態」を「注文時に選択必須」に設定して保存する（Acceptance Scenario 1-3）。

**期待結果**: `GET /menus` のレスポンスに `optionGroups` が含まれ、保存内容が反映されている。

## シナリオ2: 注文時のオプション選択（User Story 2 / FR-004〜007）

1. ホール画面からグループを開き、「梅酒」を注文する際に「ソーダ」を選択して確定する。
2. 注文明細の金額が商品価格のまま（追加課金なし）であることを確認する（Acceptance Scenario 2-1）。
3. 「レモンサワー」を注文する際に「メガサイズ」（+200円）を選択して確定する。
4. 注文明細の金額が「商品価格+200円」になっていることを確認する（Acceptance Scenario 2-2）。
5. 「氷の状態」（必須）を設定した「梅酒」の注文で、オプションを選択せずに確定しようとし、確定できずエラー表示されることを確認する（Acceptance Scenario 2-3）。
6. オプション未設定の既存商品を通常通り注文し、従来通り動作することを確認する（Acceptance Scenario 2-4、後方互換）。

**期待結果**: `POST /orders` が必須未選択時に400エラー（`missingRequiredOption`）を返す。正常時は`OrderItem.price`に追加金額が反映される。

## シナリオ3: 厨房・会計への反映（User Story 3 / FR-006〜008）

1. 「メガサイズ」を選択した「レモンサワー」を注文後、キッチン画面を開く。
2. 調理チケットに商品名とあわせて「メガサイズ」が表示されることを確認する（Acceptance Scenario 3-1）。
3. オプション追加課金を含む複数商品を注文したグループの会計画面を開く。
4. 合計金額にすべてのオプション追加金額が正しく合算されていることを確認する（Acceptance Scenario 3-2）。

## シナリオ4: 割引オプション・0円下限（Clarifications Q2, FR-007）

1. 任意の安価な商品にマイナス値の選択肢（例: -100円）を持つオプション分類を追加する。
2. 商品価格よりマイナス額が大きい選択肢を選んで注文し、明細金額が0円未満にならず0円でクランプされることを確認する。

## シナリオ5: 分類・選択肢の削除と過去注文への非影響（Edge Cases, FR-010）

1. シナリオ2で注文した「梅酒」の商品設定から「氷の状態」オプション分類を削除する。
2. 過去の注文明細（`OrderItemOption`）の内容・金額が変更されていないことを確認する（伝票・会計履歴等の表示で確認）。

## 自動テストとの対応

- Backend unit test: 必須バリデーション（missingRequiredOption）、択一制約違反（duplicateOptionGroupSelection）、0円クランプ、全置換更新のnested write挙動。
- Frontend unit test: オプション選択ボトムシートの選択状態管理、必須未選択時の確定ボタン無効化。
- e2e（Claude側で実行）: シナリオ1〜3を通しで実行し、Socket.io経由の`menu:updated`/`order:created`反映も含めて確認する。
